# 取关狗

取关狗浏览器扩展源码，支持为 Chrome、Edge、Firefox 和 Opera 构建对应版本。包含「私人账号」和「社区名单」两种独立模式：私人账号可比对当前 X 账号的关注／粉丝关系，找出没有回关你的账号；社区名单模式可查看经审核的共享名单，并在明确确认后分批拉黑。**它不追踪谁最近取关你，也不提供历史取关记录。**

**截至 2026-09-26，取关狗社区名单当前有效收录 138 个账号。**

## 安装

1. 在 Chrome 地址栏打开 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目中的 `extension` 文件夹。
5. 先在 Chrome 中登录 `x.com`，再点击工具栏里的“取关狗”。

## 在线名单与本地备用

名单唯一源文件保存在 `data/blocklist.json`。发布后，GitHub Pages 会把它提供为在线名单：`https://711stoner.github.io/quguangou/extension/data/blocklist.json`。插件打开时优先读取在线名单；如果在线请求失败，会先使用上一次成功缓存，再回退到随扩展打包的本地备用名单。发布者可以加入 X 用户链接、`@用户名`、裸用户名或数字用户 ID，例如：

```json
{
  "version": "2026-09-09",
  "updated_at": "2026-09-09",
  "description": "需要拉黑的账号名单",
  "accounts": [
    "https://x.com/example_account",
    "@another_account",
    "123456789"
  ]
}
```

从 v0.2.14 开始，只更新名单不需要重新发布扩展。修改 `data/blocklist.json` 并推送到 GitHub 后，等 GitHub Pages 部署完成，已安装插件的用户再次打开插件即可读取最新名单。只有插件代码、权限、界面或运行逻辑发生变化时才需要提交 Firefox / Edge / Chrome / Opera 新版本。普通用户界面不提供编辑名单的入口。

## 使用

打开扩展即可查看社区名单。该名单不是根据当前用户的粉丝或关注关系生成的。点击“开始处理第 1 批”后，扩展会创建一个非活动标签页，并按分批节奏依次处理账号：每批最多 20 个，一批结束后强制冷却 30 分钟；冷却结束后，下一批必须由用户再次手动点击继续。例如 100 个账号需要分 5 批、手动操作 5 次。账号之间仍保留操作间隔。

任务结果保存在 `chrome.storage.local`，关闭扩展弹窗不会清空进度。点击“停止任务”可取消尚未处理的账号。冷却期间可通过次级入口主动跳过，但必须先确认风险；默认建议等待完整 30 分钟。跳过冷却会提高连续自动操作频率，可能增加触发 X 频率限制、验证、账号功能受限或暂停等风控的概率。名单会持续更新，用户可以之后再回来查看新增名单并继续分批处理。每批进入拟人化冷却时会提供一张可选的 X 推文广告价值估算入口；全部处理完成后也会提供一张完成场景入口。首页不显示估值入口，同一状态不会重复显示两张；不会强制跳转。

## 注意

- 建议先用 1–2 个测试账号确认当前 X 页面可以正常识别。
- 扩展依赖 X 网页的按钮和菜单结构；X 改版后可能需要更新选择器。
- 扩展不会读取或保存 X 密码。社区名单会从在线源读取；私人账号检测进度与白名单默认保存在当前浏览器。只有用户主动确认提交社区名单时，符合条件的处理结果才会按隐私说明进入审核流程，不会在用户未确认的情况下自动公开。
- 请控制批量规模和使用频率，并遵守 X 的适用条款。


## 扫描末尾与受限账号处理

扫描接近列表末尾但人数尚有差额时，会提示核对最后一段；不会虚构缺失账号。如果完成后 X 主页总数仍高于实际可读取人数，结果会提示可能误判。私人账号的已确认取关任务遇到 X 受限账号提示（例如 `Caution: This account is temporarily restricted`）时，先识别明确的 `Yes, view profile`（查看主页）按钮，并只点击一次。即使提示文字被换行，或按钮被 X 放在弹窗之外，也会尝试识别。点击后等待真实主页加载，再核对登录账号、目标、白名单和是否仍然关注，然后才能进行取关。不点击一般法律、Cookie 或付费订阅授权，不把「查看主页」算作取关成功。


## 付费订阅页面安全关闭

私人账号取关遇到 X `/username/creator-subscriptions/subscribe` 时，先尝试点击唯一明确的关闭按钮，再返回原目标主页，核对账号、白名单、关注关系并按原任务执行取关。不会点击 Subscribe/付款按钮；如无法定位关闭按钮则直接导航到原账号主页，若仍被遮挡则安全跳过，最多尝试一次。


## 白名单本地持久化与保护（重要）

- 白名单只储存在**当前浏览器资料中的当前插件安装 ID**，按当前 X 账号分别保管。更换桌面解压目录、移除并重新添加未打包扩展，可能导致 Chrome 生成另一个插件 ID。即使仍用同一个 Chrome，新插件也无法读取另一插件 ID 的存储。以后始终只使用 `桌面/取关狗/` 加载并在原位置更新，不能卸载或清除扩展数据。
- 新版继续兼容原来的 `quguangouPersonalWhitelistV1`，并在每次添加／移除后写入独立的浏览器**本地备份** `quguangouPersonalWhitelistBackupV1`、记录保存过白名单的账号标记，且从存储重新读取两份进行校验；成功后才提示「已加入白名单」。不使用云同步或网络上传。
- 当前主记录缺失但备份存在时自动恢复；旧版只有主记录时自动建立备份。若已经留下「曾保存过」标记却两份名单都无法读取，则报错并停止相关操作，不能把读取失败当作空白名单继续取关。
- 如果当前安装实例的白名单实际为空，批量操作确认框必须明确提示这一点，后台也会拒绝未经确认的取关/拉黑任务；防止因插件安装 ID 变化而误以为以前保存的账号仍受保护。
- 侧栏区分「正在读取…」「读取失败—（可重试）」和「确实没有找到名单 0」，显示名单所属的 @X 账号。若没有最新扫描但只有一个历史保存账号，也尽量显示其本地记录。请注意：**这无法找回 Chrome 已经删除的其他扩展安装 ID 的数据**；不要声称已恢复尚未找到的账号。


## 国际化功能与商店 SEO 的边界（2026-11-04）

- 个人账号的扫描与批量操作依附用户当前 X 账号，**不会因切换中文／英文／其他界面语言而隐藏原任务**。社区共享名单则仍分语言分区；个人任务若主动提交社区，保留创建任务时的社区语言归属，不会在切换界面时悄悄迁移。
- 11 份项目地区资料对应 10 种可选 UI 语言：`zh_CN`（简体）、`zh_TW`（繁体台湾）、`zh_HK`（香港繁体**兼容资源**，使用繁体界面）、en、ja、ko、fr、es、ms、vi、id。Chrome 官方扩展语言列表没有单独 `zh_HK`，因此不能当作可选的独立 Chrome 商店语言，使用 `zh_TW` 上架繁体。
- `商店SEO文案.json` 是唯一的本地化标题、摘要、全文、Edge 搜索词源文件；`scripts/sync-store-seo.py` 同步 `_locales` 并刷新唯一上架指南。**上传 ZIP 不会自动完成所有商店的详细介绍或截图**，需要后台分别确认。
- 统一保留三个固定包名，但**如商店已发布 v0.2.74 或更高，下一次代码上架前必须增加 `manifest.version`**，并重新覆盖这三个文件才能提交。保持固定文件名与提高正式发布版本号并不矛盾。
- `scripts/audit-store-assets.py` 只读检查 11 地区 × 3 浏览器既有素材的 PNG 结构和尺寸。素材多为旧截图，实际画面内容上架前仍需人工复核。


## 测一测／本地化广告入口

- 十种界面语言：首页、个人和社区等普通页面始终在页面底部显示一个可选估价入口；正在冷却的任务使用冷却入口；已完成的任务使用完成入口，每个场景只显示一张卡片，不再采用随机出现逻辑。
- 语言跳转路径分别为 `zh-cn`、`zh-hant`、`en`、`ja`、`ko`、`fr`、`es`、`ms`、`vi`、`id`，香港繁体与台湾繁体共用 `zh-hant`。所有跳转只携带固定 `utm_source=quguangou`、`utm_medium=extension` 和 `utm_campaign`，不携带 X 登录信息、用户名或扫描数据。


## Chrome 商店：网址名称、搜索文字与展示语言不是同一回事

- 商品 ID 是 `ahpjikfghfgekmjcomhcmknlkicloblf`。网址路径中显示中文“取关狗”或英文“Followback Watchdog”，都只是方便阅读的 URL slug，**不决定语言**。同一商品可通过 `?hl=zh-CN` 显示中文或 `?hl=en` 显示英文；不能用插件代码让 Chrome 商店搜索框根据关键词自动选择语言。
- 本地 `_locales` 的标题和摘要随着**安装包审核发布**才更新线上；详细介绍和本地化截图必须另外在 Chrome 商店开发者后台每种语言填写／提交。`scripts/audit-chrome-store-locales.py --report` 自动检查 10 种语言线上表现并更新《商店线上语言核验.md》。
- 当前公开商店对应中文、英文；另外 8 种语言仍回退到简体。这个状态是线上公开页面读取得到，**不能将尚未上传的 v0.2.75 包标成线上修复完成**。
- `scripts/audit-store-assets.py --report` 检查 33 组（含香港繁体兼容）原有素材及十种语言 Chrome 截图哈希，再把逐语言截图路径写入同一核验报告。原图来自 v0.2.55–v0.2.70，尺寸与字节差异不代表已验证全部图片内容。
