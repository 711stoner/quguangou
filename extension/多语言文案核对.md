# 取关狗｜多语言文案核对记录

更新日期：2026-11-03；当前扩展版本 v0.2.74。统一维护目录：`桌面/取关狗/`。

## 核对范围

- 商店语言／地区配置：**11 个**（zh_CN、zh_TW、zh_HK、en、ja、ko、fr、es、ms、vi、id）。`zh_TW` 和 `zh_HK` 共用繁体中文翻译，界面提供 **10 种可选语言**。
- 以简体中文功能定义为基准，核对所有语言的首页、两种模式、关注检测、操作按钮、错误反馈、暂停/恢复窗口、429 限流提示、白名单、社区名单、隐私页面以及浏览器商店的短标题/简介。
- 审查静态 HTML、浏览器商店 `_locales/*/messages.json`、动态翻译词典和浏览器中的实际运行结果。

## 发现并修复

1. **繁体中文：** 清理“讀取消追蹤注你的人”误写，统一为“讀取追蹤你的人”；纠正“頁面過載”对“页面重载”的错误理解，改为“頁面重新載入”；隐私页面“許可權”“發帖內容”调整为更自然的“權限”“貼文內容”，并统一异常提示用词。
2. **英文和繁体中文：** 补齐之前只在简体中文实现的扫描窗口消失、几分钟无进度的动态检测/提示；不再让固定文案覆盖实际运行中的状态说明。
3. **日、韩、法、西、马来、越、印尼文：** 修复扫描进度中未替换的 `Followers` / `Following`，补齐“扫描停滞”的动态翻译，消除旧版“正在快速读取”不准确的暗示。调整拼接片段中丢失空格的问题，包括马来语、越南语、印尼语的数字和单位。
4. **西班牙语：** 修正 `Fase ... terminado` 的性别搭配，使用 `completada`。
5. **印尼语、马来语、越南语：** 清理重复引用的语言切换样式表。
6. **十语言按钮：** 统一英文、繁体中文及部分语言的窗口重开按钮与帮助文案用词，减少“强制重开”造成的误解。

## 验收

- 静态检查：11 个地区翻译包完整；10 种界面的 85 个 HTML 控件 ID 全部一致；各隐私页面主要章节数量一致；非中文界面（日本语除外）的 HTML 不包含汉字残留。
- 动态检查：Chromium 隔离测试档案模拟了 **扫描窗口消失／进度停滞、用户手动暂停、X HTTP 429 冷却**，逐一检查 10 种界面语言显示、按钮和主要进度信息；未发现页面脚本错误。
- 自动化：`node --test test/locale-copy.test.mjs test/scan-stall-help.test.mjs test/scan-pacing.test.mjs` 通过 18 项测试。
- Chrome、Edge、Firefox 发行包仍使用 `quguangou-chrome.zip`、`quguangou-edge.zip`、`quguangou-firefox.zip` 固定名称覆盖，不另起版本。

## 边界

- 这些是本地的文本、规则及模拟浏览器验收，不是有偿的母语译者逐句认证。部分罕见的 X 服务器错误文本仍由安全的本地化通用错误提示兜底，不能保证 X 未来新增的报错文案永不变更。
- 商店图片（已存储的多个版本）并未在本轮重新渲染/逐张审阅图片文字；商店图片的语言和截图版本应在上架前单独复核。
- 尚未将新安装包提交浏览器商店；不要卸载正在使用的插件或清空浏览器中扫描断点数据。


## 2026-11-03：逐语言结构与动态状态复核（第二轮）

**以简体中文页面为基准，不改变既定功能和 X 扫描算法。**

### 涉及语言和地区

- 11 个商店地区包：`zh_CN`、`zh_TW`、`zh_HK`、`en`、`ja`、`ko`、`fr`、`es`、`ms`、`vi`、`id`。
- 十种可选界面；台湾、香港共同使用繁体中文界面，保留两套商店地区资源。

### 本轮发现与修复

1. 其他语言页脚原先比简体中文多一个“网站”链接，英文/繁体又使用专属 CSS，导致同一页面不同语言有不同结构或字体规则。现已统一为同一套 HTML 元素层级与公共 CSS；保留语言本身文字长短造成的自然换行。
2. 西班牙语首页 `Comprueba quién te sigue de vuelta` 原意为“查看谁回关你”，与核心功能恰好相反；改为 `Descubre quién no te sigue de vuelta`。法语个人账号模式说明改为更自然的从句。
3. 马来语、越南语、印尼语的动态任务文案拼接丢失空格，如 `Kelompok1 / 2selesai`、`65halaman`、`Tahap1` 等；对 64 组动态句段做边界空格核对与修复，状态与数字重新分隔。
4. 英文动态按钮存在 `Block selected (2）` 这种英文左括号配中文右括号；改成匹配的 `(2)`。日语“保護リスト（0)”也改成完整的全角括号“保護リスト（0）”。
5. 静态「重新打开扫描窗口（保留进度）」在部分语言中仍写成“强制重开”，而动态运行时已是柔和的新文案；现统一初始和动态文本。
6. 更新 README 中过期的“没有个人关系检测”“完全不会提交社区审核数据”等介绍，避免与功能及隐私说明矛盾。

### 核实结果

- **静态同构**：十种界面相同元素排列顺序、85 个 ID、共用 CSS、相同页脚结构。所有入口和资源路径存在；11 个商店地区包完整。
- **浏览器状态**：隔离的 Chromium 浏览器配置中，逐一模拟模式选择、个人扫描已完成、社区批次冷却/暂停等三种页面状态。10 语言 × 3 状态 × 320px/340px 两种宽度，共 60 个页面布局快照；无横向页面溢出、无浏览器脚本异常。
- **真实交互模拟**：逐语言切换、打开个人账号、返回模式选择均通过，每语言 45 个基础按钮，未测试真正的 X API 调用。
- **自动化回归**：`node --test test/store-seo.test.mjs test/locale-copy.test.mjs test/locale-layout-and-runtime.test.mjs test/scan-stall-help.test.mjs test/scan-pacing.test.mjs`。

### 2026-11-03｜X 受限主页的二次识别与实际浏览器模拟验收

问题：私人账号取关时遇到 `Caution: This account is temporarily restricted` + `Yes, view profile`，之前的任务直接将部分账户记为「已跳过」。

代码改动：

1. X 受限警告的标题允许多行文字、拆分 DOM 节点，检测时统一空白字符。
2. 在 X 页面骨架加载阶段等待受限提示或实际关注控件出现，避免页面尚未渲染就判定失败。
3. 精确识别 `Yes, view profile`／「查看主页」等按钮；支持按钮在主栏、弹窗或 X Portal 兄弟容器。若找出多个候选，或只有泛用 `Agree`、Cookie/服务协议按钮，不自动点击。
4. 点击后不立即认定取关成功，后台仍重新核对登录账号、目标账号、白名单。X React 视图切换较慢时最多等待约 10 秒让关注控件出现，不重复点击受限提示。
5. 只有实际找到 `Following`、确认 `Unfollow` 并核实操作后的状态变化，才记录 `unfollowed`；否则保持安全失败/跳过状态。
