# 取关狗 v0.2.73：X 429 限流保护（2026-11-03）

## 问题与调整
原扫描会在 X 自身的虚拟列表加载之外，按捕获的 GraphQL 模板主动补发 cursor 分页请求；快时每 2.5–4.5 秒一次，可能叠加 X 页面本身的请求。X 可以按账号、会话、接口动态限流，因此无法保证任何扫描频率永不返回 429。

本版默认完全停用插件主动补发 cursor GraphQL 请求，保留从已加载 DOM 与自然网络响应读取用户的逻辑，允许速度下降。扫描循环开始时读取 X 自身分页请求的诊断信息；若收到近期 HTTP 429，立即停止后续滚动，按保存的断点和响应中可用的 Retry-After / reset 信息进入冷却。不清空关注/粉丝及游标断点。近两小时内的 429 失败次数不因偶然成功一页而清零，避免重试环。

## 已验收
- 静态脚本语法及 pacing 单元测试 4/4 通过。
- 在模拟 X 页面中验证真实 Chromium 扩展窗口重开、原扫描断点保留及暂停行为。
- 模拟 3797 关注、2438 粉丝的大检查点保存、冷却保护与重复点击防护通过。
- 模拟 429 到期后经插件唤醒建立新独立窗口，断点保存不丢失。
- 三浏览器发行包 ZIP 构建、内容完整性及 SHA-256 复制校验。

## 上线边界
- **未**用真实 X 账号执行数千人的完整扫描，也未测得真实生产环境的 429 触发频率改善幅度。
- 不得把 HTTP 429 理解为可以通过延迟或伪装完全消除的错误。服务器配额和 Retry-After 必须被尊重。
- 本版未上传商店。Chrome/Edge/Firefox 的包仅为待手动验收的候选版本。
- 关闭主动 cursor 请求后，深度扫描可能显著慢于过去；需要用真实账号确认正常页面能持续加载全部列表。
